LT-02服务规格

图号 LT-02 / 比例 1:1 / 日期 2026-11 / 版本 2.4

四件事，
都从「读不懂」开始。

我们通常不接「只做视觉稿」的单。界面是系统结构的显影；结构没理清，视觉只会把问题包得更漂亮。下面四张规格表都写了「不接什么」——写清边界，比列一堆能力更有用。

表格读法：范围是做什么，输入是你需要提供的人与材料，输出是可验收的交付物，周期是常见区间而非承诺。

01

B 端产品界面

7 人 · 常见周期 4–8 周 · 后台、工作台、审批流、复杂表单。

表 02-01

规格：B 端产品界面

使用者一天要用八小时，效率比惊艳重要。正常态之外，空态、加载、错误、无权限四类状态一并定义。

表 02-01 · 范围 / 输入 / 输出 / 验收 / 不接 / 周期
范围任务流拆解、信息架构、页面与状态设计、可用性走查；后台、工作台、审批流与复杂表单。
输入现有系统与报表；业务、值班员、IT 三方可受访；一名能拍板的决策人。
输出任务流图、页面清单、可点击原型、高保真界面、状态清单、走查记录。
验收页面清单全部可点；四类状态齐全；1366 与 1920 宽下无横向溢出；前端能按标注独立实现。
不接只想要一套「看起来高级」的皮；没有能拍板的决策人；要求先免费出三版看看。
周期4–8 周，取决于页面数量与要对接的系统数量。
任务流信息架构状态设计可用性走查设计交接
02

数据大屏

5 人 · 常见周期 3–6 周 · 指挥中心、展厅、监控大屏。

表 02-02

规格：数据大屏

按观看距离决定信息密度，按值班场景决定告警层级。离屏 3 米和 30 厘米，字号与密度不是一套。

表 02-02 · 范围 / 输入 / 输出 / 验收 / 不接 / 周期
范围指标梳理与口径对齐、图表选型、大屏信息分层、动效与性能约束。
输入指标口径与业务确认人；真实数据样例（脱敏）；现场观看距离与值班场景。
输出指标清单、图表使用规范、大屏视觉稿、动效说明、数据表兜底方案。
验收3 米与 5 米观看距离下关键数字可读；指标口径表经业务确认；断网或无数据时有兜底画面。
不接把大屏当海报做；数据源与刷新频率还没定；要求所有指标都上首屏。
周期3–6 周，含至少一次现场观看距离测试。
指标梳理图表选型信息分层动效数据表兜底
03

设计系统

前端 4 人 · 常见周期 6–10 周 · 多产品线共用一套约束。

表 02-03

规格：设计系统

让第 100 个页面不用重新设计，也不用重新争论。前端从第一天参与，命名先于视觉。

表 02-03 · 范围 / 输入 / 输出 / 验收 / 不接 / 周期
范围色彩 / 字号 / 间距 / 圆角 / 阴影 Token；组件库与命名规则；设计文件与前端 CSS 变量映射；维护机制。
输入前端从第一天参与；现有组件与命名清单；多产品线的页面清单。
输出Token 表、组件库、使用规范、前端变量映射表、培训录屏、维护说明。
验收新页面只用现有组件即可完成约 80%；Token 与前端变量一一对应；团队能独立新增一个组件。
不接没有前端参与；希望一套系统同时覆盖 Web、App、小程序且不做取舍。
周期6–10 周，含一轮真实页面试点，不是只交一份文档。
Design Token组件库命名规则前端映射维护机制

设计系统不是一次性项目：交付后 3 个月内的组件增补与规范答疑，我们按小时支持，不强制签年框。

04

设计咨询

2 人 · 常见周期 2–4 周 · 给一页可执行的清单，不给厚报告。

表 02-04

规格：设计咨询

内部有设计与前端、但缺方法或缺外部视角时，咨询比执行更合适。通常可拆成两次各半天现场。

表 02-04 · 范围 / 输入 / 输出 / 验收 / 不接 / 周期
范围现有界面走查、指标与信息架构诊断、设计评审机制搭建、团队方法培训。
输入现有界面与评审记录；内部设计与前端成员；需要对齐的分歧点。
输出一页问题清单（按影响排序）、走查记录、改进路线、一次 2 小时工作坊。
验收问题清单每条有责任人与建议动作；工作坊后团队能独立跑一次评审。
不接希望用咨询替代执行；需要一份「证明我们做得对」的报告。
周期2–4 周，可拆成两次各半天现场。
界面走查诊断评审机制工作坊
05

表 02-05 · 服务总览

放在一张表里看。周期是常见区间，不是承诺；真正排期要看过系统、数据和决策链之后才给。

表 02-05 · 四类服务的周期、交付与适用阶段
服务典型周期核心交付什么时候需要
B 端产品界面4–8 周任务流、原型、界面与状态清单系统要改版，或从 0 到 1
数据大屏3–6 周指标清单、图表规范、大屏视觉指挥中心、展厅、监控场景
设计系统6–10 周Token、组件库、前端映射多产品线开始各做各的
设计咨询2–4 周问题清单、路线、工作坊团队有执行力，缺方法与判断

表中周期不含客户侧评审与数据准备时间；这两项通常是延期的主要原因。

06

表 02-06 · 启动方式

从一句话开始，不用先写正式 brief。三步之后才进入报价与排期。

表 02-06 · 启动三步
编号动作说明
01发一句现状现在卡在哪、系统大概什么样、希望什么时候开始。三行字就够，不用附件。
0260 分钟诊断线上通话。我们问问题，你看我们是否听得懂。不适合的项目，当场说，并给一个方向。
03一页范围与报价做什么、不做什么、周期、区间报价、需要你配合的人和材料。确认后再启动。

不接急单。如果档期排不开，我们会直说，并推荐可能合适的人。
